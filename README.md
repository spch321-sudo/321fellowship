- **空閒自動套用補強（實測後修正）**：以真實 Service Worker＋模擬 GitHub Pages 快取（max-age=600）實測，原本的更新模組有三個缺口：① 同一個新版會連續觸發兩次（版本檔輪詢＋SW 安裝完成同時偵測到），第二次就直接走「硬更新」，把 SW 登出後重整時 HTTP 快取還留著舊的 JS，可能重整完仍是舊版、更新條卡著；② 忙碌判斷沒有包含「輸入框有未存內容」；③ 硬更新會清掉整個網域所有 App 的快取、登出所有 App 的 Service Worker。
- 現改用共用自動更新模組（AUPD）：偵測（載入後 2.5 秒、回前景、每 30 分鐘、恢復連線、SW 安裝完成）→ 空閒自動套用，不必按；重整前先重抓主要檔案繞過 HTTP 快取，再登出本 App 的 SW 避免新舊 SW 交接時導覽卡住；忙碌（朗讀、錄音錄影、小智回答、輸入框有內容、共讀、面板／工作室開著）只顯示更新條，忙完自動套用；同一版只自動重整一次，再失敗清「自家 k321- 前綴」快取硬更新一次，仍失敗只留更新條。
- 只接受自己這支 sw.js 的 sw-updated 通知（同網域別支 App 的 SW 也會廣播），並回頭讀 version.json 確認，避免跨 App 誤重整；sw.js 通知只送給自己範圍內的視窗。
